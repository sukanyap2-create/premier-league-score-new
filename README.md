# แดชบอร์ดพรีเมียร์ลีก

แดชบอร์ดพรีเมียร์ลีกแบบปรับตามหน้าจอ สร้างด้วย React, Vite, Node.js และ Express ใช้ football-data.org API v4 เป็นแหล่งข้อมูลสด โดยเก็บ API token ไว้บนเซิร์ฟเวอร์เท่านั้น และไม่รวม token ในโค้ดที่ส่งไปยังเบราว์เซอร์

โปรเจกต์นี้รองรับเฉพาะพรีเมียร์ลีก (`PL`) ไม่มีตัวเลือกลีกหรือหน้ารวมรายการแข่งขันอื่น โปรแกรม ตารางคะแนน สโมสร และประวัติการแข่งขันของสโมสรจะแสดงเฉพาะข้อมูลพรีเมียร์ลีก

## ความสามารถ

- หน้าภาพรวมพรีเมียร์ลีก แสดงโปรแกรมและสรุปตารางคะแนน
- โปรแกรมและผลการแข่งขันพรีเมียร์ลีก พร้อมตัวกรองสถานะ นัดแข่งขัน และช่วงวันที่
- ตารางคะแนนและรายชื่อสโมสรพรีเมียร์ลีก
- บันทึกสโมสรโปรดไว้ในเบราว์เซอร์ พร้อมแสดงอันดับและคะแนนบนหน้าภาพรวม
- เปรียบเทียบสถิติของสองสโมสรจากข้อมูลที่ API ส่งกลับ
- แสดงผลงานห้านัดล่าสุดเมื่อ API มีข้อมูล
- รายละเอียดสโมสรและประวัติการแข่งขันในพรีเมียร์ลีก
- การ์ดรหัสย่อสโมสร (TLA) และโค้ชจาก API
- ชื่อเจ้าของสโมสรจากชุดข้อมูลแยก (ไม่ได้มาจาก football-data.org)
- สถิติเหย้า–เยือน คำนวณจากผลการแข่งขันพรีเมียร์ลีกที่จบแล้วและ API ส่งกลับ
- รายชื่อผู้เล่นแยกตามตำแหน่งผู้รักษาประตู กองหลัง กองกลาง และกองหน้า; ซ่อนผู้เล่นที่ไม่ทราบตำแหน่ง พร้อมแสดงวันที่ข้อมูลอัปเดตและคำเตือนเมื่อข้อมูลเก่า
- รายละเอียดการแข่งขันและสถิติการพบกัน (H2H) เฉพาะพรีเมียร์ลีก เมื่อแพ็กเกจ API อนุญาต
- ค้นหาสโมสรและการแข่งขันพรีเมียร์ลีก
- ตั้งค่าแหล่งข้อมูล API/ข้อมูลตัวอย่าง ธีม และล้าง cache ในเบราว์เซอร์
- สถานะกำลังโหลด ไม่มีข้อมูล ข้อมูลสำรองเก่า ข้อผิดพลาด และข้อมูลที่แพ็กเกจไม่รองรับ
- เมนูด้านข้างและเมนูมือถือแบบปรับตามหน้าจอ ป้ายกำกับที่เข้าถึงได้ การ์ดคะแนน และกราฟจากข้อมูลตารางที่ API ส่งกลับ
- ระบุโหมดตัวอย่าง (Demo) ให้ชัดเจนเมื่อไม่มี API token; ไม่นำข้อมูลตัวอย่างไปแสดงว่าเป็นข้อมูลจริง
- สำรองคำตอบ API ที่โหลดสำเร็จไว้บนเซิร์ฟเวอร์ เพื่อใช้ชั่วคราวเมื่อ API ต้นทางขัดข้อง

ระบบไม่สร้างข้อมูลผู้เล่นบาดเจ็บ เหตุการณ์สด รายชื่อผู้เล่นตัวจริง อัตราต่อรอง สถิติผู้เล่น หรือคะแนนที่ไม่มีในแหล่งข้อมูล football-data.org ไม่มีข้อมูลอาการบาดเจ็บและเจ้าของสโมสรในข้อมูลทีม จึงระบุข้อมูลบาดเจ็บว่าไม่มีให้บริการ และใช้ชุดข้อมูลเจ้าของสโมสรที่ดูแลแยกจาก API รายชื่อผู้เล่นจะแสดงเมื่อมีอยู่ในข้อมูลทีมของ API พร้อมวันที่อัปเดต และเตือนเมื่อวันที่เก่าหรือไม่มีวันที่ คะแนนและวันที่จะแสดงตามข้อมูลจากแหล่งที่เลือกเท่านั้น คะแนนและโปรแกรมใน Free Plan อาจล่าช้า

## เกณฑ์งานและหลักฐานการทำงาน

### ก่อนปรับปรุง → หลังปรับปรุง

| ก่อนปรับปรุง | หลังปรับปรุง |
|---|---|
| แสดงข้อมูลพรีเมียร์ลีกพื้นฐาน เมนูมีจำกัด และรับมือเมื่อ API ขัดข้องได้น้อย | แดชบอร์ดเฉพาะพรีเมียร์ลีก ปรับตามหน้าจอ มีหน้าภาพรวม โปรแกรม/ผล ตารางคะแนน สโมสร รายละเอียดทีม/แมตช์ ค้นหา และตั้งค่า |
| เบราว์เซอร์อาจต้องเรียกผู้ให้บริการข้อมูลโดยตรงหรือส่งคำขอซ้ำ | React เรียก API ภายใน Express เก็บ token ฝั่งเซิร์ฟเวอร์ ตรวจตัวกรอง จำกัดข้อมูลเป็น `PL` จัดคิวคำขอ cache คำตอบ และบันทึกข้อมูลสำรอง |
| ค้นหาโดยตรวจชื่อทีมทีละรายการทุกครั้งที่พิมพ์ | React สร้างดัชนี substring เมื่อรายชื่อทีมเปลี่ยน แล้วค้นหาจากดัชนีเมื่อพิมพ์ โดยไม่ส่งคำขอ API เพิ่ม |

### โครงสร้างคอมโพเนนต์ React และการไหลของสถานะ

```text
main.jsx
└─ App (DashboardApp: หน้า, โหมด, รายการที่เลือก, ตัวกรอง, สโมสรโปรด, ธีม)
   ├─ Sidebar / MobileNav
   └─ ตัวแสดงผลของหน้าที่เลือก
      ├─ PageHeading / Card / MetricCard / StatusNotice
      ├─ MatchTable / StandingsTable / TeamGrid / PointsChart
      └─ useResource → api.js → พร็อกซี /api ของเว็บเดียวกัน
                         └─ เส้นทาง Express → football-data.org
```

`useResource` ดูแลสถานะกำลังโหลด สำเร็จ ไม่มีข้อมูล ใช้งานไม่ได้ ข้อผิดพลาด และข้อมูลสำรองเก่าของแต่ละรายการ `StatusNotice` ใช้บทบาทการเข้าถึง `status`/`alert` เพื่อให้ผู้ใช้เห็นและโปรแกรมอ่านหน้าจอแจ้งข้อความได้ รายการว่างมีข้อความแจ้งเฉพาะ และข้อผิดพลาดจะไม่ถูกแปลงเป็นข้อมูลว่างหรือสถานะสำเร็จ

### โครงสร้างข้อมูลและความซับซ้อนของ DSA

- **ดัชนี substring และ HashTable (React):** สร้างจากรายชื่อสโมสรพรีเมียร์ลีกที่ API ส่งกลับใน `src/App.jsx` ใช้ทั้งตัวกรองหน้าสโมสรและหน้าค้นหา `src/dsa.mjs` เก็บ substring ด้วย Hash Table แบบ separate chaining และขยายตารางเมื่อ load factor เกิน `0.75` เมื่อข้อความค้นหายาว `q` และมีรายการชนกันใน bucket จำนวน `c` การค้นหาใช้เวลา `O(q·(c+1))`; หากกระจายค่า hash ดี ค่าเฉลี่ย `c` จะต่ำ กรณีเลวร้ายคือ `O(q·K)` เมื่อมี key ที่จัดทำดัชนี `K` รายการ หากข้อความทีมยาว `L_i` จะมี substring ได้สูงสุด `O(ΣL_i²)` รายการ ส่วนการสร้าง คำนวณ hash และเก็บอักขระของ substring ใช้ `O(ΣL_i³)` การขยายตารางแบบเรขาคณิตเพิ่มต้นทุนไม่เกินตัวคูณลอการิทึมของจำนวน key โดยประมาณ ใช้กับรายชื่อเพียง 20 สโมสร และ memoize ดัชนีไว้ จึงไม่สร้างซ้ำทุกครั้งที่พิมพ์หรือเรียก API เพิ่ม
- **Merge Sort (React):** `StandingsTable` ใช้ `mergeSort` ที่เขียนเองและรักษาลำดับเมื่อค่าเท่ากัน เมื่อผู้ใช้เลือกเรียงตามคะแนน จำนวนชนะ ผลต่างประตู หรือประตูได้ ใช้เวลา `O(n log n)` และหน่วยความจำชั่วคราว `O(n)` อันดับทางการจาก API ยังคงแสดงอยู่แม้เรียงด้วยสถิติอื่น และรายการที่คะแนนเท่ากันจะคงลำดับเดิม
- **ผลต่อ UX ก่อนและหลัง:** ก่อนทำดัชนี ทุกครั้งที่พิมพ์จะตรวจข้อความของทีมทั้ง `n` รายการ หลังโหลดรายชื่อทีม ระบบสร้างดัชนีหนึ่งครั้ง แล้วค้นหาด้วย Hash Table ในกรณีทั่วไปโดยไม่ไล่ตรวจทุกทีม ข้อความในหน้าค้นหาและตัวเลือกเรียงตารางแสดงให้เห็นตำแหน่งที่ใช้อัลกอริทึม
- **หน้าที่ของ Express:** การค้นหาและเรียงข้อมูลที่โหลดมาแล้วทำบนฝั่งผู้ใช้ เพราะเป็นข้อมูลขนาดเล็ก ส่วน Express รับผิดชอบปกป้อง API token ตรวจข้อมูลนำเข้า จำกัดเส้นทางให้เป็นพรีเมียร์ลีก จัดคิวคำขอ cache และเก็บข้อมูลสำรองถาวร

### แนวทางบันทึกคลิปนำเสนอ (6–8 นาที)

1. **0:00–0:45 — ปัญหาและแนวคิด:** แนะนำโจทย์พรีเมียร์ลีกเดิมและข้อจำกัดที่ต้องการปรับปรุง
2. **0:45–1:30 — ก่อนปรับปรุงและหลังปรับปรุง:** แสดงการทำงานเดิมเทียบกับแดชบอร์ดปัจจุบัน อธิบายเมนูและการรับมือเมื่อ API ขัดข้อง
3. **1:30–3:00 — สาธิต UX:** เปิดโปรแกรม ตารางคะแนน ค้นหา/รายละเอียดสโมสร และรายละเอียดแมตช์ แสดงสถานะโหลด แหล่งข้อมูล ข้อผิดพลาด หรือรายการว่างเมื่อมี
4. **3:00–4:15 — React และ Express:** อธิบายผังคอมโพเนนต์และสถานะด้านบน ไล่คำขอหนึ่งครั้งจาก `useResource` ผ่านพร็อกซีไป API และชี้ให้เห็นว่า token อยู่บนเซิร์ฟเวอร์
5. **4:15–5:45 — สาธิต DSA:** ค้นหาด้วยส่วนหนึ่งของชื่อสโมสร แล้วเรียงตารางด้วยสถิติ อธิบาย Big-O การแลกเปลี่ยนด้านหน่วยความจำ และเหตุผลที่ดัชนีเหมาะกับ 20 สโมสร
6. **5:45–6:45 — ความทนทานและการทดสอบ:** แสดงป้าย cache/ข้อมูลสำรอง หรือโหมด Demo โดยระบุว่าเป็นข้อมูลตัวอย่าง แล้วรายงานผลทดสอบและ build
7. **6:45–7:30 — สะท้อนงานรายบุคคล:** สมาชิกแต่ละคนบอกส่วนที่ตนเองทำ การตัดสินใจหนึ่งข้อพร้อมข้อแลกเปลี่ยน และสิ่งที่อยากปรับปรุงต่อ

โปรเจกต์ช่วยเตรียมการสาธิตและหลักฐานได้ แต่ทีมต้องบันทึกวิดีโอจริง และสมาชิกแต่ละคนควรอธิบายผลงานของตนเองตามความเป็นจริง

## ข้อจำกัดของ API และแพ็กเกจ

หน้า Free Plan ระบุว่ามีคะแนน โปรแกรม/ตารางแข่งขัน และตารางลีกที่อาจล่าช้า พร้อมจำกัด 10 คำขอต่อนาทีสำหรับรายการแข่งขันที่รองรับ การเข้าถึงแต่ละเส้นทางและความครอบคลุมขึ้นอยู่กับ token และบัญชี football-data.org เป็นแหล่งข้อมูลหลัก หากเส้นทางตอบกลับว่าไม่มีสิทธิ์หรือไม่ครอบคลุม หน้าเว็บจะแจ้งว่าไม่มีข้อมูล แทนการสร้างข้อมูลหรือใช้ข้อมูลจากแพ็กเกจที่มีค่าใช้จ่ายแทน

เส้นทาง API ภายใน Express ที่รองรับข้อมูลพรีเมียร์ลีก:

| เส้นทางภายใน | ทรัพยากรต้นทาง |
|---|---|
| `GET /api/competitions` | `/competitions` |
| `GET /api/competitions/:code` | `/competitions/:code` |
| `GET /api/competitions/:code/standings` | `/competitions/:code/standings` |
| `GET /api/competitions/:code/teams` | `/competitions/:code/teams` |
| `GET /api/competitions/:code/matches` | `/competitions/:code/matches` |
| `GET /api/matches` | `/matches` |
| `GET /api/matches/:id` | `/matches/:id` |
| `GET /api/matches/:id/head2head` | `/matches/:id/head2head` |
| `GET /api/teams/:id` | `/teams/:id` |
| `GET /api/teams/:id/matches` | `/teams/:id/matches` |

พารามิเตอร์คำขอจะถูกจำกัดรายการที่อนุญาตและตรวจสอบความถูกต้อง รายการแมตช์และแมตช์ของทีมรองรับการแบ่งหน้าด้วย `limit`/`offset` คำตอบถูก cache ในแต่ละโปรเซสเป็นเวลา 90 วินาที และคำขอไป API ต้นทางถูกจัดคิวให้ห่างกัน 6.5 วินาที (ประมาณ 9 คำขอต่อนาที) เพื่อไม่ให้เกินเพดาน Free Plan และรวมคำขอซ้ำเข้ากับ cache การอัปเดตข้อมูลทำโดยผู้ใช้กดเอง ไม่ทำอัตโนมัติ คำตอบ API ที่โหลดสำเร็จจะบันทึกไว้ที่ `.cache/football-data-backup.json` (Git ไม่ติดตามไฟล์นี้) หาก API หมดเวลา ใช้งานไม่ได้ หรือจำกัดจำนวนคำขอ เซิร์ฟเวอร์อาจส่งข้อมูลล่าสุดที่บันทึกไว้ พร้อมคำเตือนว่าข้อมูลเก่าและเวลาที่บันทึก ข้อมูลสำรองนี้อยู่ต่อเมื่อรีสตาร์ตเซิร์ฟเวอร์ แต่ไม่ได้แชร์ระหว่าง serverless instances หากนำไป deploy หลาย instance ควรใช้พื้นที่จัดเก็บหรือ cache ที่แชร์ร่วมกัน

## เริ่มใช้งานในเครื่อง

สิ่งที่ต้องมี: Node.js 18 ขึ้นไป

1. ติดตั้งแพ็กเกจ:

   ```sh
   npm install
   ```

2. สร้างไฟล์ `.env` ที่โฟลเดอร์หลักของโปรเจกต์ แล้วใส่ token ของ football-data.org:

   ```env
   FOOTBALL_DATA_TOKEN=your_token_here
   PORT=3000
   ```

   อย่า commit ไฟล์ `.env` หรือใส่ token ในซอร์สโค้ด หากเคยเปิดเผย token ในที่สาธารณะหรือแชต ให้ยกเลิก token เดิมและสร้าง token ใหม่

3. เปิดเซิร์ฟเวอร์ API:

   ```sh
   npm start
   ```

4. เปิดเทอร์มินัลอีกหน้าต่าง แล้วเริ่ม Vite พร็อกซี `/api` จะอ่าน `PORT` จาก `.env` (ค่าเริ่มต้น `3000`); หาก Express อยู่ที่ที่อยู่อื่น ให้ตั้ง `VITE_API_PROXY_TARGET`:

   ```sh
   npm run dev
   ```

   เปิด URL ภายในเครื่องที่ Vite แสดง คำขอ `/api` จะถูกส่งต่อไปยัง Express

หากไม่ได้ตั้ง token แดชบอร์ดจะเข้าโหมด Demo พร้อมป้ายกำกับข้อมูลตัวอย่าง เลือก **ตั้งค่า → Football-Data.org API** หลังเพิ่ม token และรีสตาร์ต Express ข้อมูล Demo ใช้ทดลองหน้าจอเท่านั้น และอาจเก่าหรือไม่ครบถ้วน

## สร้าง ตรวจสอบ และนำขึ้นใช้งาน

```sh
npm run build
npm run preview
```

`npm start` ให้บริการทั้ง production build และ API routes หากนำขึ้น Vercel ให้กำหนด `FOOTBALL_DATA_TOKEN` เป็น Environment Variable ฝั่งเซิร์ฟเวอร์ `api/index.js` รับคำขอ API ผ่าน rewrite ใน `vercel.json` แล้วส่งเส้นทางเดิมเข้า Express ส่วน cache และตัวจำกัดคำขอในหน่วยความจำแยกกันในแต่ละ instance
